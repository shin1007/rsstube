| ジョブ | 間隔 | 何をするか |
|---|---|---|
| poll | 毎時 07分 | 18本を巡回。301 の移転を追い、失敗が続けばサイトから探し直す |
| worker | 5分ごと | 本文抽出 → 要約 → 台本 → 音声合成。45秒で切り上げる |

| media-purge | 毎日 3:45 | 30日を過ぎた音声を Storage ごと削除 |

## 今日見つけて直したバグ

どれも「静かに壊れる」型で、エラーも出ずに間違った結果を出していました。

| 何が | どうなっていたか |
|---|---|
| **既読・スター・あとで** | `onConflict` が主キーと合わず `42P10` で全部失敗。**押しても何も起きていなかった** |
| **`htmlToText`** | linkedom の使い方を誤り**常に空文字**を返していた。生HTMLが要約に渡っていた |
| **東洋経済の本文** | 記事ではなく約4,000字のナビゲーションメニューを保存していた（13件） |
| **記事の改行** | `textContent` がブロックの境目に何も入れないため、見た目が書き手のHTML次第だった |
| **Shift_JIS のページ** | 文字化けしたまま「成功」扱いで要約に回っていた（厚労省など） |
| **バックアップ** | `subscriptions` が 0005 以降ずっと漏れ、さらに jsonb が原因で**復元できなかった** |
| **ダイジェスト** | 「ちょうどその時刻」判定で、cron が1回転ぶと丸一日欠けていた |
| **`media` の重複防止** | NULL 混じりの UNIQUE が効かず、同じ音声を2本作れた |
| **重要度の「?」** | スクロール枠に切られて読めなかった |
| **検索語** | カンマや括弧を打つと 400 になっていた |

### 判断が要るもの

- **本文とみなす下限を 100 字にしました**（もとは200）。データ上は3件悪化・2件改善で
  判断が割れる程度でした。要約の質が落ちたと感じたら `MIN_CONTENT_CHARS` を 200 に
  戻してください。影響は `npm run check:url -- <URL>` で個別に確かめられます

## 見送った判断

無理に作らなかったものと、その理由。

- **pgvector で重複記事をまとめる** — 作る前に測ったら、直近400件で似た記事は4組（約1%）
  だけでした。1%のために毎記事へ埋め込みを付けるのは割に合いません。フィードを増やして
  重なりが目立ってきたら、そのとき作るのが正しいです
- **外部の本文抽出API（Jina Reader）** — 実際に困っている2フィード（Aeon・東洋経済）で
  両方とも弾かれました。効くのは元々取れているサイトだけです
- **エラーページ判定の定型文マーカー** — 誤検出が多く、8件中4〜5件が本物の記事でした
  （アクセス解析の記事の "unusual traffic" など）。代わりに「冒頭が毎回同じ」で判定しています
- **PGroonga の `&@~` 演算子** — 索引を張るだけで8.2倍速くなったので、いまはそこまで。
  さらに25倍にできますが、PostgREST から呼べず RPC でクエリ経路が二重になります
