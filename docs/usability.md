# 競合と比べて、何が足りないか

2026-09-03 調査。**目的は機能を増やすことではない。**「毎朝この1本で読み切れるか」
だけを基準に、他のリーダーが当たり前に持っていて、こちらに無いものを並べる。

前提を先に置く（`CLAUDE.md` の決まりごとから）:

- **個人用**。共有・チーム・公開は当面やらない
- **スマホが主、朝と晩**。PCは補助
- **AI要約が入口**。見出しではなく要点3つを読んで、開くかどうかを決める
- **無料枠に収める**。増やす機能は Gemini と Supabase の枠を食わないこと

## 立ち位置

| | 強み | こちらとの違い |
|---|---|---|
| **Inoreader** | ルールと自動化、検索が全期間、フィルタが細かい。2026年に任意のプロンプトを記事に当てる Inoreader Intelligence が入った | 向こうは「取りこぼさない」道具。こちらは「読む数を減らす」道具 |
| **Feedly** | Leo による要約・重複排除・話題フィルタ。無料は3フィードまで | 要約は同じ土俵。**重複排除はこちらに無い** |
| **NetNewsWire** | 無料・広告なし・軽い。Apple 純正級の作法。AIは無し | 操作の作法（スワイプ・キーボード）はここを手本にするとよい |
| **Reeder** | 読み味と操作。スワイプの割り当てを自分で変えられる | 同期は別サービスが要る。こちらは自前で完結している |

**こちらが既に勝っているところ**（守るべきもの）:

- 要点3つが一覧の行に出る。開かずに捨てられるのは Feedly Pro 相当
- 本文の取得が強い（PDF・別ページ追跡・文字コード・枠の誤検出まで対処済み）
- 音声化とスライド、NotebookLM への書き出し

## 足りないもの（優先順）

順番は「毎日の手数がどれだけ減るか ÷ 作る手間」で付けた。
**入れ終わったものはこの一覧から抜く**（残っているものだけを見れば済むように）。
入れたぶんは #109 / #111 / #112 / #113 / #135 / #143 にある——まとめて既読・共有・未読バッジ・
文字の大きさ・読了の目安・引っぱって更新・スマホのフィード引き出し（ドロワー）の7つ、
それに **2（検索の範囲が画面に出ていない → #135。絞り込みの名札と、0件のときの行き先）**と
**3（通勤中に読めない → #143。未読20件を持ち出して圏外で読める。既読の同期は入れていない）**。

### 4. 同じ話題が別のフィードから何度も来る

Feedly の Leo が売りにしている重複排除。こちらは `content_hash` を
「同じページの使い回し」検出に使っているだけで、**別フィードの同じ話題**は素通し。
要約のタグと `title_ja` があるので、材料はある。

- **どう作るか**: まずは「同じ日・同じタグ3つ以上・見出しの類似」で
  一覧上でまとめて折りたたむだけ。消さない
- 手間: 中〜大。**急がない**（購読12本ならまだ痛くない）

## やらないと決めるもの

- **同期・複数端末での既読位置**。1人用なので要らない
- **ルールエンジン**（Inoreader 相当）。「点数が低い記事を自動で既読にする」も
  ここに含む。**誰にとって低いのかを決められない**仕組みの上には積まない
  （重要度を廃止した理由と同じ。CLAUDE.md）。読む量を減らす手が要るなら、
  AI に間引かせるのではなく、読む人自身の操作（購読を減らす・既読にする）を
  軽くするほうから当たること
- **タグ付けの手作業**。要約が自動で付けている。人が付け直す運用は続かない
- **記事のハイライト・メモ**。NotebookLM へ書き出す経路がその役目を持っている
