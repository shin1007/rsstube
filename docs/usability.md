# 競合と比べて、何が足りないか

2026-09-03 調査。**目的は機能を増やすことではない。**「毎朝この1本で読み切れるか」
だけを基準に、他のリーダーが当たり前に持っていて、こちらに無いものを並べる。

前提を先に置く（`CLAUDE.md` の決まりごとから）:

- **個人用**。共有・チーム・公開は当面やらない
- **スマホが主、朝と晩**。PCは補助
- **AI要約が入口**。見出しではなく要点3つを読んで、開くかどうかを決める
- **無料枠に収める**。増やす機能は Gemini と Supabase の枠を食わないこと

## 立ち位置

| | 強み | こちらとの違い |
|---|---|---|
| **Inoreader** | ルールと自動化、検索が全期間、フィルタが細かい。2026年に任意のプロンプトを記事に当てる Inoreader Intelligence が入った | 向こうは「取りこぼさない」道具。こちらは「読む数を減らす」道具 |
| **Feedly** | Leo による要約・重複排除・話題フィルタ。無料は3フィードまで | 要約は同じ土俵。**重複排除はこちらに無い** |
| **NetNewsWire** | 無料・広告なし・軽い。Apple 純正級の作法。AIは無し | 操作の作法（スワイプ・キーボード）はここを手本にするとよい |
| **Reeder** | 読み味と操作。スワイプの割り当てを自分で変えられる | 同期は別サービスが要る。こちらは自前で完結している |

**こちらが既に勝っているところ**（守るべきもの）:

- 要点3つが一覧の行に出る。開かずに捨てられるのは Feedly Pro 相当
- 重要度が数字で出て、それで並べ替えられる
- 本文の取得が強い（PDF・別ページ追跡・文字コード・枠の誤検出まで対処済み）
- 音声化とスライド、NotebookLM への書き出し

## 足りないもの（優先順）

順番は「毎日の手数がどれだけ減るか ÷ 作る手間」で付けた。

### 1. まとめて既読にする手段が「全部」しかない（済 #109）

いまは `全既読`（読み込んだぶん全部）だけ。**その中間が無い。**
NetNewsWire・Inoreader・Feedly はどれも「この記事より上（新しい方）を既読」
「このフィードを既読」を持っている。朝に30件たまっていて、上から5件読んで
残りは要らない、という日にいまは一件ずつ捌くか全部捨てるかしかない。

- **どう作るか**: 行の長押し（PCは右クリック）で「ここから下（古い方）を既読」。
  一覧はすでに並び順が確定しているので、`id` の位置で切って `setReadMany` に渡すだけ
- **注意**: 取り消し（UndoBar）を必ず通すこと。既読は戻せないと怖くて押せない
- 手間: 小

### 2. 共有が無い（済 #109）

スマホで読んで、誰かに送る・自分のメモに送る導線がゼロ。元記事を開いてから
ブラウザの共有を使うしかない。`navigator.share()` の1行で、要約つきで渡せる。

- **どう作るか**: 記事の帯に1つ足す。渡すのは「訳した見出し＋元URL」。
  要点3つも入れるかは好みなので、まず見出しとURLだけ
- **注意**: `navigator.share` はPCの一部ブラウザに無い。無いときはボタンを出さない
  （押して何も起きないのが一番悪い）
- 手間: 小

### 3. アプリのアイコンに未読の数が出ない（済 #109）

ホーム画面に置いてあるのに、開くまで新着があるか分からない。通知は
ダイジェストのときだけ鳴る。`navigator.setAppBadge()` は PWA で使えて、
通知の許可とは別枠（許可済みならそのまま出せる）。

- **どう作るか**: サイドバーの未読数を出しているのと同じ値を、画面を描いたときに
  `setAppBadge` へ渡す。サービスワーカー側の push でも更新する
- 手間: 小

### 4. 重要度を「並べ替え」にしか使っていない

`importance` を毎回 Gemini に付けさせているのに、使い道が並べ替えだけ。
Inoreader のルールに相当するものが、こちらでは**すでに材料だけ揃っている**。

- **どう作るか**: 設定に「重要度がこの数より低い記事は最初から既読にする」を1つ。
  要約が付いた時点（ワーカー）で `is_read` を立てる
- **注意**: 既読にするのであって消さない。「すべて」ビューには残す。
  そして**閾値を上げすぎると気づけない**ので、既定は無効、変更したら
  「先週なら何件が既読になっていたか」を出す
- 手間: 中

### 5. 通勤中に読めない（オフライン）

サービスワーカーは意図的に何もキャッシュしていない（`public/sw.js`）。
地下鉄で開くと `offline.html` が出るだけ。**朝の通勤前に開くのが主な使い方**
だと決めてあるのに、そこが弱い。

- **どう作るか**: 一覧を開いたときに、先頭N件の本文だけを静かに取って
  Cache Storage に置く。オフラインのときは記事ページをそこから描く
- **注意**: 既読やスターは書けないので、オフライン中の操作は溜めて後で送る
  ——ここまでやると別物の複雑さになる。**まず「読めるだけ」で切る**
- 手間: 大（だが効き目も大きい）

### 6. 文字の大きさを自分で変えられない（済 #111）

`docs/traps/ui.md` にあるとおり、文字の大きさは3回作り直している。
毎回コード側の目盛りを動かしていて、**読む人が決められない**。
NetNewsWire も Reeder も本文の文字サイズは設定にある。

- **どう作るか**: 設定に3段階（小・中・大）。`@theme` の目盛りを CSS 変数で
  上書きするだけなので、クラスは1つも触らなくてよい
- 手間: 小

### 7. 読了の目安が無い（済 #109）

要点3つで「読むかどうか」は決まるが、「いま読めるか（3分か15分か）」が分からない。
Readwise Reader や Matter は必ず出している。`content_text` の文字数から出せる
（日本語は約500字/分）。

- 手間: 小

### 8. 同じ話題が別のフィードから何度も来る

Feedly の Leo が売りにしている重複排除。こちらは `content_hash` を
「同じページの使い回し」検出に使っているだけで、**別フィードの同じ話題**は素通し。
要約のタグと `title_ja` があるので、材料はある。

- **どう作るか**: まずは「同じ日・同じタグ3つ以上・見出しの類似」で
  一覧上でまとめて折りたたむだけ。消さない
- 手間: 中〜大。**急がない**（購読12本ならまだ痛くない）

### 9. 引っぱって更新できない（済 #112）

巡回は1時間ごとの pg_cron。いま欲しいときに取りに行く手段が画面に無い。
スマホの一覧を引っぱったら巡回を1回叩く、はほぼ全てのリーダーにある。

- **注意**: 連打で無料枠を食うので、最短でも数分は間隔を空ける
- 手間: 小

### 10. 検索の範囲が画面に出ていない（当初の見立ては誤り）

**「検索が絞り込みを無視する」と書いたが、確かめたら無視していなかった。**
フィードを選んだまま「新型」で引くと、別のフィードでは0件、そのフィードでは
10件で、条件はきちんと重なっている（手元の実データで確認）。

残っている問題は別のところにある。**いま何の中を探したのかが画面に出ない。**
0件だったとき、「どこにも無い」のか「このフィードに無い」のかが区別できない。
一覧の見出しはビュー名（未読・すべて…）しか出しておらず、フォルダ名も
フィード名も出ていない。

- **どう作るか**: 見出しの横に、絞り込んでいるフィード／フォルダの名前を出す。
  0件のときの文面にもそれを入れる
- 手間: 小。ただし**次の項目を先にやること**——スマホではそもそも
  フィードを選べないので、いま出しても出番が無い

### 11. スマホからフィード・フォルダで絞り込めない

**調査中に見つけた、いちばん大きい穴。** フィードとフォルダを選べるのは
サイドバーだけで、それは `hidden md:flex`——つまり**スマホには存在しない**。
下部タブにあるのはビュー（読む・あとで・スター）だけ。設定の「フィード管理」も
絞り込んだ一覧へは行かない。

フォルダは11個、フィードは12本ある。**整理してあるのに、主に使う端末では
その整理を使えない。**「今日は Tech だけ読む」ができない。競合はどれも
モバイルでフィード一覧を持っている（そもそもRSSリーダーの基本画面）。

- **どう作るか**: サイドバーの中身を切り出して、スマホでは引き出し（横から出る
  パネル）として同じものを出す。一覧の見出しに「フィード」ボタンを1つ
- **注意**: 下部タブに7つ目を足さないこと。いまでも6つで1行ぎりぎり
  （`docs/traps/ui.md` の「入るはずだったものが入らなくなる」）
- 手間: 中。**ただし効き目はこの一覧で最大**。10 はこれとセットで意味を持つ

## やらないと決めるもの

- **同期・複数端末での既読位置**。1人用なので要らない
- **ルールエンジン**（Inoreader 相当）。4 の閾値1つで足りる。増やすと設定画面が
  読めなくなる
- **タグ付けの手作業**。要約が自動で付けている。人が付け直す運用は続かない
- **記事のハイライト・メモ**。NotebookLM へ書き出す経路がその役目を持っている

## 次にやるなら

手間の小さいもの（1・2・3・6・7）は入れ終わった。残りはこの順:

1. **11（スマホからフィードを選べない）** — 中だが、いちばん効く。10 はこれとセット
2. **4（重要度で自動既読）** — 材料は揃っている。既定は無効にして、
   「先週なら何件が既読になっていたか」を出してから決めてもらう
3. **5（オフライン）** — 効き目は大きいが設計が要る。やると決めてから別に切る
4. **8（重複排除）** — 購読12本ならまだ痛くない。急がない
