# 踏んだ罠 — Gemini と無料枠

lib/ai/ · 要約 · 台本 を触るときに読む。索引は `CLAUDE.md` にある。

**ここに書くのは「決まったこと」ではなく「実際に壊れた話」だけ。**
同じ壊れ方をもう一度させないための記録なので、直し方だけでなく
「どう見えたか（何が起きているように見えたか）」を残すこと。

- **`responseSchema` の `maxItems` は「項目3つまで」なら使える。** 7つの
  オブジェクトに付けると `INVALID_ARGUMENT` で弾かれる（理由が本文に出ないので
  原因不明の400に見える）。**そして上限はプロンプトでは守られない。**
  スライドの項目が7つで `maxItems` を諦めていたとき、モデルが同じスライドを
  延々と繰り返して出力トークンを使い切り（実測23302トークン・73639字）、
  **記事1本からの音声生成は必ず失敗していた**。ダイジェスト（8件）では起きないので
  気づきにくい。いまはスライドを `{type, heading, body[]}` の3項目に平たくして
  `maxItems` を効かせ、受け取ってから型ごとの形に戻している（`lib/ai/script.ts`）。
  項目を増やしたくなったら、この壊れ方が戻ることを思い出すこと。

- **`maxOutputTokens` は思考トークンも含む。** 3.5-flash は答える前に考えるので、
  8192 にしたら思考だけで使い切って本文が716字で切れた。絞るときは
  `thinkingBudget` も一緒に指定する。`finishReason === 'MAX_TOKENS'` を見て
  「打ち切られた」と分かるようにしてある（見ないと JSON の parse エラーとして
  出てきて原因が分からない）。

- **長さは「合計で何字」ではなく「1枠に何字」で頼む。** ダイジェストの台本で
  「合計4400字」と頼んで返ってきたのは3545字（81%）だった。ところが**同じ生成の
  スライドごとの字数は 344/509/459/465/467/512/501/288 とよく揃っていた**——
  モデルは全体の目標より、目の前の枠に割り当てられた数のほうを守る。
  15分に伸ばすとき、合計を5100字に増やすのではなく「1つの話題につき1125字」と
  割り当て直したら、実測は 1081/1099/1053/1141、合計4981字＝14.7分に収まった。
  枚数（`maxItems`）と同じで、**個数や割り当てで言うと従う**。

- **`gemini-3.5-flash` の無料枠は1日20リクエスト。** 台本生成1本で1回使う。
  デバッグで何度も叩くとその日ぶんが尽きる（実際に尽くした）。
  使用量は設定画面の表で見られる。要約の flash-lite とは別枠。
  **無料枠と上限の全体は `docs/quotas.md` にまとめてある。**公開情報だと
  Flash 系は500〜1500 RPD と書かれていることが多いが、手元のキーは20だった。
  外の数字ではなく `ai_usage` と 429 の本文（`limit:` が書いてある）を見ること。
