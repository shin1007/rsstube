# 踏んだ罠 — 取り込みと本文抽出

lib/feeds/ · 巡回 · 要約に渡すもの を触るときに読む。索引は `CLAUDE.md` にある。

**ここに書くのは「決まったこと」ではなく「実際に壊れた話」だけ。**
同じ壊れ方をもう一度させないための記録なので、直し方だけでなく
「どう見えたか（何が起きているように見えたか）」を残すこと。

- **`res.text()` は日本語のサイトで文字化けする。** Content-Type に charset が無いと
  UTF-8 として読むが、自治体・省庁には Shift_JIS / EUC-JP が現役で残っていて、
  charset を meta にだけ書いていることがある（例: `mhlw.go.jp`）。
  厄介なのは**化けても長さはあるので抽出は「成功」に見える**こと。化けた文字列が
  そのまま要約に回る。`lib/feeds/charset.ts` で Content-Type → BOM → meta の順に見る。

- **本文が取れないサイトに、こちら側の直しどころは無い……が、3つに分けて数えること。**
  110件の実測（`docs/site-compat.md`）で失敗したのは9件、すべて 403/401/429 だった。
  ブラウザと同じ User-Agent にしても結果は変わらないので、UA ではなく
  IP か TLS 指紋で弾かれている。**UA を偽装しても意味が無い**ので、
  正直な UA を名乗り続けること。
  ただし**「サイト単位で読めるか」と「記事単位で取れたか」は別物**だった。
  2026-08-26 に本番の失敗567件を叩き直したら、3種類に割れた:
  - **本文がHTMLに無い**（東洋経済347件・全体の61%）。200 は返るが Readability が
    掴むのはグローバルメニュー。0016/0018 の使い回し判定が正しく弾いている。直せない
  - **弾かれている**（Hacker News185件・33%）。リンク先が第三者のサイトで 403/401、
    または JS でしか描かれない。直せない
  - **一度失敗しただけ**（Aeon21件ほか・6%）。**いま叩けば2万字の本文が返る。**
    `extracted_at` が入ると「処理済み」になり、二度と取りに行かない作りだった
  3つ目のために `0028` で理由（`extract_fail`）を残し、`network` と `short` のときだけ
  6時間後に1回だけ取り直す。**`recycled` と `blocked` は取り直さない**——
  東洋経済と Hacker News で毎日20件ぶん、何も変わらない取得を繰り返すことになる。

- **フィード単位の「読めなさ」はどの数字にも出ない。** 取得は 200 で成功し続け、
  新着も毎日来るので `error_count` も `last_article_at` も正常なまま、要約だけが
  RSS の抜粋から作られて薄くなる。東洋経済は427件中347件（81%）がこの状態で、
  設定画面には何も出ていなかった。`feed_content_stats()`（`0028`）で数え、
  `lib/feeds/health.ts` が半分を超えたフィードを「本文が取れない」として出す。
  **割合だけで判定しないこと。** 件数の下限（10件）が無いと、購読したての
  フィードがほぼ必ず引っかかる。

- **巡回は `feeds` を直に見てはいけない（`0029`）。** feeds は全ユーザー共通で
  購読の有無を持たない（0005）ので、直に select すると**購読をやめたフィードも
  毎時取りに行き続ける**。記事は入り続け、本文抽出も要約（Gemini の無料枠）も走るのに、
  画面には出ないので表からは分からない。掃除（`purge_orphan_feeds`）任せにもできない
  ——あれはスターや書き出し済みの記事が1件でも残っているフィードを消さないので
  （消すと記事ごと巻き添えになる）、印を付けた記事があるフィードは解除後も
  永久に残り、永久に巡回される。18本を外したとき、11本がこれに当たった。
  `feeds_to_poll()` を使うこと。

- **`articles.url_hash` は全体で一意。** フィードごとではない。同じ記事URLを配る
  フィードを2本登録すると、**後から購読したほうには過去記事が1件も入らない**
  （insert が conflict で落ちるだけなので、エラーにもならず「新しいフィードが空」に
  見える）。実例: `nazology.net/feed` と `nazology.kusuguru.co.jp/feed` は
  別ホストだが中身は同じで、記事リンクはどちらも kusuguru を指す。
  乗り換えるときは `articles.feed_id` を新しい行へ移すこと。

- **`JST` は JavaScript が解釈できない。** `new Date('Wed, 26 Aug 2026 17:00:00 JST')` は
  `Invalid Date`。RFC 822 が名前で認めているのは UT / GMT と北米の4つ（EST・CST・
  PDT など。**これらは V8 がそのまま読む**）だけで、`JST` `KST` `MSK` `CEST` は入っていない。
  rss-parser も `new Date()` に任せているので `isoDate` が付かない。
  **静かに壊れる**——取り込みも本文も要約も普通に通り、`published_at` だけが null になる。
  一覧は `nulls last` なので**その記事が全部末尾に沈む**（千葉県の103件＝全体の29%が
  この状態だった。「新着なのに一番下」としか見えない）。`lib/feeds/date.ts` で
  名前のタイムゾーンを読み替える。**表に足すのは「世界で1つに決まる略号」だけ**——
  `CST`（北米中部/中国）や `IST`（印/以/愛）を入れると、静かに違う時刻が入る。

- **要約に「本文が取れなかった」ことを書かせない。** プロンプトに
  「(注: 本文が取得できず、RSSの抜粋のみ)」とだけ渡していたら、モデルが素材の
  乏しさのほうを要約してきた（実データで30件が「本文が取得できずRSSの抜粋のみのため、
  詳細な内容を確認することはできない。」だけになっていた）。**漫画のフィードは本文が
  無いのが当たり前**なので全話がこれで埋まり、しかも1件ぶんの無料枠を使う。
  読み手が知りたいのは記事の中身であって、こちらの取得結果ではない。

- **直したら、それが既存の行にも届くか確かめること。** 取り込みは `ignoreDuplicates`
  なので、`JST` を読めるようにしても**既に入っている記事の日付は埋まらない**。
  そのたびに手で UPDATE を流すのでは、気づいた人がいるときしか直らない。
  `backfill_published_at()`（`0030`）を取り込みの経路に置いて、その回の取得に
  入っていた項目ぶんだけ埋め戻す。全記事を浚うわけではないので
  「後から全記事を浚う処理を足さない」には反しない。次に別の略号へ対応したときも、
  次の巡回で勝手に追いつく。

- **先回りで塞げないものは、欠けたことが見えるようにする。** タイムゾーンの略号を
  全部表に入れることはできない（`MSK` `CEST` …）。`feed_content_stats()` が
  日付なしの件数も数え、8割を超えたフィードを健康診断に「日付が無い」として出す。
  閾値を半分にしないのは、日付を打たない項目が混ざるフィードが普通にあるため。

- **消毒で枠を外した子は、もう一度見直すこと。** 走査は `Array.from(node.children)` の
  写しを回すので、知らないタグを `replaceWith(...childNodes)` で外すと、
  **その中身はその回では一度も訪れない**。属性が絞られず、相対URLも直らない。
  見つかったきっかけは画像だった——厚労省・PLOS などで `<img src="/content/…">` が
  相対のまま保存され、ブラウザがこちらのドメインを見に行って404（39記事）。
  同じ記事でも直接の子だった img は絶対URLに直っている、という混ざり方をする。
  **危ないのは属性のほう。**知らないタグの中に `<img onerror=…>` を置かれると
  その on* が残る。実データに混入は無かったが、それは入力の運。
  外したぶんがあれば同じ節をもう一度walkする（`0026` ではなく `sanitize.ts`）。

- **HTMLに本文が無いページは、本体が別にある（PDF・別ページ）。** 官公庁と自治体に多い形で、
  表題とリンクだけのHTMLに中身が付いていない。厚労省の「○○医療費の動向」がこれで、
  本体のPDFは35ページ・54,605字あった。`lib/feeds/followup.ts` が1段だけ辿り、
  PDFは `unpdf` で読む（`lib/feeds/pdf.ts`）。記事URLが直接PDFのときも読む
  （以前は「HTMLではない」で捨てていた。Hacker News のPDFリンクもこれに当たる）。
  ここで踏んだものを順に:
  - **失敗ではなく「成功」に見えていた。** 入口ページでは Readability が掴むものが無く、
    代わりに**フッターを本文として返す**。実例で返ってきたのは
    「〒100-8916 …Copyright ©…」の118字で、`MIN_CONTENT_CHARS`（100）を超えているので
    抽出成功として保存され、`feed_content_stats()` にも出てこない。
    なので本体を疑う境目は別に持つ（`FOLLOW_BELOW_CHARS` = 600）。
  - **枠の判定に body の class を混ぜない。** 厚労省は `<body class="t-mhlw nav03">`。
    `nav` に当たるので、素直に祖先を遡ると**そのページのリンクが1本残らず枠扱い**になり、
    候補ゼロで静かに何もしなくなる。BODY と HTML は見ないこと。
  - **辿った先が本体でないほうが怖い。** 「取れなかった」は見れば分かるが、
    「関連ページの本文がこの記事として要約されている」は読んでも気づけない。
    臆病に倒す: 別サイトは追わない / 候補が4つ以上あるページ（一覧・目次）は何も追わない /
    `…/` や `index.html`（節の入口）は本体にしない——千葉県の「協議会の開催について」から
    一段上を読み、その回の案内ではなく協議会そのものの説明を本文にしていた /
    **辿った先が今より200字以上増えないなら辿らなかったことにする**——漫画のページで
    「最新話から」を辿ったら、行った先も同じ194字の作品紹介だった。
  - **審議会のページは先頭2本が議事次第と委員名簿。** 順番どおりに3本読むと
    「会議の次第と出席者」だけが要約される。手続き書類は後回しにして資料を先に読む。
  - **「本体はこちら」の1行はHTMLにだけ置く。** 要約に渡すテキストに入れると、
    モデルが記事の中身ではなく取得の事情を要約してくる（前科あり）。
  - 既にある記事は取り直さない（`extracted_at` があるため）。手で流すのは
    `scripts/reextract-thin.mjs`。

- **本文が短い記事では、Readability がメニューのほうを本文として掴む。** 点数は
  文字数と読点（`,`）の数から出すのに、日本語の読点は `、` なので数えられない。
  結果、リンクだらけのグローバルメニューが「長いテキスト」として勝つ。実例は厚労省の
  `stf/newpage_75898.html`（250字の記者会見の案内）で、保存されていたのは
  ヘッダーのメガメニューを含む2006字。**100字も600字も超えているので「抽出成功」に見え**、
  `FOLLOW_BELOW_CHARS` の疑いにも `feed_content_stats()` にもかからない。
  読む人には「中身が無い」としか見えない（実際にそう報告された）。
  掴んだのが枠かどうかは**返ってきたHTMLに `<header>` / `<nav>` / `<footer>` が
  残っているか**で分かる。Readability はこれらを本文の外とみなして落とすので、
  残っているのは枠ごと掴んだときだけ。疑わしければ `<main>` の中に閉じ込めて
  もう一度掴ませる（`lib/feeds/frame.ts`）。実記事33本で比べて、変わったのは3本、
  いずれも枠が落ちたぶんだけ良くなっていた。
  **`<main>` の中身は Readability に渡す前に控えること**——渡した document は
  書き換えられるので、掴んだあとに querySelector しても元の中身はもう無い。
  `<article>` は見ない（一覧ページでは記事カード1件にも付いている）。

- **枠を掴んだ記事は、既に入っているぶんが直らない。** `extracted_at` があるので
  取り直さないうえ、長さがあるので `reextract-thin.mjs` の「薄い」にも入らない。
  実データで**NHK の386件**（そのフィードのほぼ全部）がこの状態だった。
  見分け方は「同じフィードの記事が全部同じ文字で始まっている」こと——メニューは
  記事ごとに変わらない。**ただし一致するだけで積まないこと。** ダイヤモンドの連載は
  定型のリード文で始まるので同じ形に見えるが中身は本物で、積むと同じ要約を
  もう一度作るために Gemini の無料枠だけが減る（約90件あった）。組ごとに1本だけ
  実際に取り直して、結果が変わるものだけ積む（`--framed`）。
